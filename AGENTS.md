# Autoresearch rulebook

The task is to improve `val/retrieval_accuracy` on this repository's frozen benchmark. Read this file and README.md before changing anything. Run scripts; do not use notebooks as the experiment driver.

## Fixed contract

1. The score is `(validation event top-1 + validation station top-1) / 2`. Both use cosine similarity, every validation trace as a query, and every training trace as the gallery. Event retrieval uses `ze`; station retrieval uses `zs`. The evaluator fixes normalization, gallery ordering, tie handling and aggregation. Higher is better. An exact score tie prefers lower canonical validation reconstruction MSE, then the earlier epoch.
2. `benchmark/manifest.json` fixes exactly one trace per cell of the largest-found complete **N stations × N events square** in the full source graph. The number of stations and events must be equal. Selection uses deterministic greedy searches from up to the 512 highest-degree nodes on each side, with stable lexical ties. Each prefix scores `min(station_count, event_count)`; the larger side is cropped in lexical order to make a complete square. Like the reference notebook, this is a heuristic, not a proof of the global maximum. The minimum side is five. Duplicate cells use the lexicographically first trace. No trace, class, side length, subset, split, split seed, sampling rate, reconstruction target or evaluation setting may change during research.
3. The split is the frozen 90/10 permutation with NumPy seed 42. A training seed may change; it must never change the split. Every class must occur in the training gallery. This measures retrieval of known classes on unseen station/event cells; it does not measure generalization to unseen events or stations.
4. **Protected:** `benchmark/`, `data/`, `src/seissepa/{data,metrics,evaluate,contract}.py`, `scripts/{prepare_data,evaluate,verify_benchmark,leaderboard}.py`, this rulebook and tests. Do not alter, bypass, monkeypatch, copy and modify, or regenerate the benchmark/evaluator/lock to improve a score. Do not run preparation during research. Only the owner may establish a new benchmark, outside an active comparison.
5. Every run must pass `scripts/verify_benchmark.py`. The runner checks hashes before training. Run the protected standalone evaluator on a candidate before promoting it. The lock is an integrity check for accidental changes, not a security boundary against an agent that can rewrite its workspace.

## Permitted research

- Edit `src/seissepa/models.py`, `src/seissepa/losses.py`, `src/seissepa/train.py`, model/loss configs and training parameters. Add model, loss or training modules. Change architecture, preprocessing, augmentation, optimizer, loss weights, schedule, batch size, epochs and training seed. Add dependencies through `pyproject.toml` and update `uv.lock` when required; record why.
- All selected waveform samples, channels and sampling rates are available. The baseline uses the notebook's normalized 8192-sample center crop. Other models may use the full frozen raw waveform. Every model must return the fixed reconstruction target shape and one nonempty `ze` and `zs` per input trace. The two latent dimensions need not match.
- Event/station identity may be used **only** to define latent-space supervision on training data: positive/negative pairs, supervised contrastive or separation losses, auxiliary training heads, and balanced training sampling. Frozen evaluators may use labels for metrics and train-only probes/centroids.
- Model inputs must contain only `waveform` and `sampling_rate`. Never feed IDs, names, row indices, split membership, lookup tables, network/station codes, catalog joins, event/station coordinates, origin times or other explicit identity metadata into the encoder, decoder or retrieval ranking. Do not recover identity from filenames. Correlations naturally present in the permitted signals are allowed.
- Fit gradients, learned preprocessing, augmentations' learned statistics, centroids, k-NN references and linear probes on training data only. Validation is read-only and may select checkpoints and experiments. Never train on validation inputs, targets, labels or pseudo-labels; never join them to training batches. Do not use external data or pretrained weights in this fixed-data benchmark.

## Experiment procedure

1. Verify the benchmark and run the tests. Inspect `scripts/leaderboard.py` and the current best report.
2. State one hypothesis and a bounded experiment budget (maximum runs and epochs) before starting a batch. Start from the default seed 42. Use Hydra overrides or a named model/loss config; do not edit protected code.
3. Commit every source, configuration and dependency change to Git and push it to the configured upstream **before training**. Use a descriptive commit message. Training refuses a dirty tree, a missing upstream or a HEAD that differs from the upstream tracking commit. Save the commit ID in every run's provenance, checkpoint and report. Never commit credentials, datasets, caches, environments or run artifacts. Do not force-push or rewrite existing history.
4. Run `scripts/train.py`. Every comparable experiment must produce `config.yaml`, `provenance.json`, `source.tar.gz`, `history.jsonl`, `best.pt`, `metrics.json` and `report.md`. Keep unsuccessful runs and failed-run logs. Never overwrite another run or discard poor results to improve a reported average.
5. Rank completed runs on the frozen score. Report event and station scores separately, the dataset fingerprint, canonical MSE, seed, best epoch, run path and elapsed time. Diagnostics must not replace the primary objective. The example numbers in the request are formatting examples, not measured baselines or targets to copy into outputs.
6. Re-evaluate the candidate checkpoint with `scripts/evaluate.py`. Confirm exact repeatability on the same software/hardware and batch size. For a promising candidate, rerun seeds 42, 43 and 44 with the same architecture and training budget; report all three and their mean/std alongside the primary seed-42 comparison. Never select a lucky seed as the only reported result.
7. Append the hypothesis, exact command, outcome and decision to `experiments/journal.jsonl`, then commit and push the journal and any resulting code/configuration changes. Keep the best valid configuration and checkpoint. Stop at the declared budget; summarize the evidence and remaining hypothesis. Do not continue an unbounded autonomous search.

Validation is used for research and selection. Repeated tuning makes its score optimistic; do not claim an untouched test result or invent confidence intervals for the mean of the two retrieval tasks. Wilson intervals apply to individual reported accuracies, not the combined objective.
